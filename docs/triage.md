# Issue and Pull Request Triage

The repository uses two gh-aw workflows for triage. Triage only classifies work,
requests missing information, and records a routing decision. It never edits
repository code, creates a PR, merges a PR, or closes an Issue or PR.

## Workflow-owned labels

The triage workflow owns exactly one category label and one state label. Labels
outside this table are preserved.

| Label | Color | Meaning |
| --- | --- | --- |
| `bug` | `d73a4a` | Category: defect or broken behavior |
| `enhancement` | `a2eeef` | Category: improvement, feature, or requested capability |
| `needs-triage` | `fbca04` | State: incomplete, conflicting, or requires human review |
| `needs-info` | `d876e3` | State: concrete reporter information is required |
| `ready-for-agent` | `0E8A16` | State: a complete next-step brief exists; it does not start an agent |
| `ready-for-human` | `1D76DB` | State: a human implementation or merge decision is required |
| `wontfix` | `ffffff` | State: no automatic implementation or closure |

`triage-paused` (`B60205`) is a manual suppression label, not a triage state.
While it is present, both workflows exit without changing labels or comments.
Remove it only when automatic reevaluation is wanted.

`ready-for-dev` is a legacy label. It no longer triggers implementation.

## Trigger paths

- `triage-conversation.md` handles newly opened Issues and human-created Issue
  or PR comments.
- `triage-pr-ci.md` handles same-repository PRs after a completed `CI`
  `workflow_run` and fork PRs through `pull_request_target` plus polling for a
  completed `CI` run with the matching head SHA.
- Bot/system events and comments generated by this workflow are ignored.
- A visible `Triage event: ...` footer prevents duplicate comments. PR results
  are also rejected when the current head SHA is newer than the event SHA.

The agent has read-only GitHub MCP tools. The trusted validator in
`scripts/triage_conclusion.py` is the only code that writes managed labels or
comments. Fork PR content is never checked out, downloaded, or executed by the
triage stage.

## Rollback

Disable `triage-conversation` and `triage-pr-ci` with `gh aw disable`. Existing
labels and comments remain. Do not reactivate the removed `issue-to-pr`
workflow automatically. Re-enabling triage requires recompiling the Markdown
sources with `gh aw compile` and rerunning the strict validation checks.
